I treat **Claude Code CLI** as a first-class part of my engineering toolchain — not a code generator, but an orchestrated team of specialist agents.

- **Custom sub-agents** for builders (`.NET API`, `Next.js routes`, `shadcn UI`) and reviewers (`security`, `query-perf`, `migration safety`, `multi-tenant gateway`).
- **Hooks** that enforce house rules at write time — no raw hex colors, no swallowed exceptions, no `--no-verify`, no force-push to `main`.

- **Slash commands** for repeatable workflows (`/review`, `/security-review`, project switchers).

The result: ship faster *without* shipping slop. The engineering judgement stays mine; the toil gets delegated.

### 🏗️ Featured architecture work — marketing-agency data & AI platform

Sole architect and engineer of an agency's full data and automation estate: a multi-tenant analytics platform, an internal tools suite, an n8n ingestion tier, and the AI agents that sit on top. *(Client and company details withheld.)*

#### 📈 Multi-tenant client analytics platform

White-label marketing reporting: staff compose a client dashboard from templates and modules and publish it with no code, no SQL, and no per-client deploy.

- **Tenancy model**: Postgres platform DB + per-client identity DB + per-tenant ClickHouse database; tenant re-resolved on every request; separate least-privilege DB roles for API, Worker, and Migrator with tests proving each is refused what it shouldn't touch; two-tenant isolation tests by default.
- **Ingestion / ETL**: leased run records → paginated, rate-budgeted extract → gzipped raw payload in MinIO with SHA-256 lineage → validate & normalize → publish to ClickHouse (ReplacingMergeTree, versioned rows, whole-window replacement) → verify counts → advance the watermark last.
- **Correct metrics by construction**: non-additive metrics (users, reach) stored per exact window, never per day, so they can't be summed wrong; a metric dictionary enforced by build-time tests.
- **Resilience**: conditional-update job claiming with lease reaping, failure classification before retry (jittered backoff), quota-aware pausing; correlation IDs traced browser → API → worker.
- **AI**: remote MCP server (Streamable HTTP, ~29 tools) behind OAuth 2.1 — PKCE, dynamic client registration (RFC 7591), discovery metadata (RFC 9728 / 8414), scoped tokens; AI edits are draft-only under row locks; pluggable LLM providers (Anthropic, OpenAI, xAI) with schema-enforced output.
- **Scale**: .NET 10 API + Worker, React 19, 74 datasets, 50 EF + 62 ClickHouse tenant migrations, 700+ integration tests, ~200 recorded architecture decisions; two-tier deploy (app / data) over WireGuard, RPO 24h / RTO 8h. Sources: Google Ads, GA4, Meta, Microsoft Ads, HubSpot, Ahrefs, call tracking.

#### 🧰 Internal operations suite

One React shell + one ASP.NET Core 10 API hosting every internal agency tool (budget pacing, PPC audit, SEO deliverables, workload, client registry, AI assistant).

- **Clean layering**: controllers → MediatR handlers → EF Core repositories + Dapper for Postgres functions, Autofac module per feature; shared zod contracts with a schema-mirror test that fails the build on DB drift.
- **Temporal data design**: effective-dated context tables and dated contract changes so closed months are never rewritten; frozen, archived periods; business invariants written into migrations that fail the migration rather than warn. 76 hand-applied SQL migrations.
- **Security**: in-process auth — 15-min JWTs + rotating refresh tokens with token-family revocation on reuse; fail-closed permission matrix; fail-open release flags that remove the API mount, not just the menu; automatic write-audit middleware.
- **Platform migration**: moved off a managed BaaS to self-hosted Postgres without breaking foreign keys, validated by diffing live dashboard output before and after.
- **8 background services**: period rollover, workload freeze, task-tracker sync with repair sweep, hourly CTV spend sync, automation-failure polling, and more.

#### 🤖 AI agents & RAG

- **Org-memory assistant**: Claude Code CLI driven per chat turn, calling tools on an n8n-hosted **MCP server**; retrieval over Qdrant, embeddings routed through LiteLLM, every call traced in Langfuse.
- **Guardrails**: per-user vault isolation via HMAC identity tokens; every tool call re-checks the caller's permission; live figures fetched by tool, never embedded; refuses rather than answer from general knowledge when retrieval is unavailable.
- **Requirements-interview agent**: interviews staff about a feature request and writes the spec.

#### ⚙️ n8n automation tier — 20+ production workflows

- **Automated PPC audit** (7-stage pipeline): SQL-scheduled orchestrator → per-client controller → memory-safe 10k-row paged ingest with bulk `jsonb_to_recordset` inserts → all calculations in SQL → LLM search-term classification → planner with 3-tier deterministic provenance validation → HTML/DOCX report. Rule: **no LLM ever computes a number.**
- **Budget pacing**: daily Google Ads / Meta API ingest and Microsoft Ads email-report ingest, natural-key upserts with exactly one producer per platform, daily alerts and weekly digests.
- **Call-transcript intelligence**: LLM classifies every call (answered / booked / topic) with automatic next-morning retry.
- **Monthly client reports**: LLM narrative written only from extracted figures, delivered as drafts — a human sends every one.
- **RAG ingest**: chunk → embed → Qdrant upsert behind a webhook.

#### 🛡️ Infrastructure

Self-hosted on a hardened Ubuntu VPS: Traefik v3 with automatic TLS, every port loopback-bound, `cap_drop ALL`, `no-new-privileges`, read-only filesystems, health checks; Postgres, Redis, n8n, Qdrant, LiteLLM, Langfuse; separate prod and QA stacks; rollback by image tag.
